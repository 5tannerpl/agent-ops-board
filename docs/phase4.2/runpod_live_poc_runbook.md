# G3 operator procedure - not authorized or executed

This is a **standalone inference** test, never a 100-Unit run. Do not start it on the basis of this document. Do not enable Azure integration, dispatch, OCI deployment, or a Dashboard control. The B.1 uncertain-Run release blocker remains open for paid end-to-end operation.

## Before spending

1. Obtain written authorization naming the dedicated account/project, endpoint, operator, earliest start, hard wall-clock stop, approved estimate, teardown owner and escalation contact. Disable automatic recharge; check current balance, outstanding usage, ability to delete, and billing access before creation. Do not modify a shared account's controls without permission. Record starting balance, timestamp, billed resource inventory, and other account traffic separately.
2. Record operator-reviewed `MODEL_REPO`, 40-hex `MODEL_REVISION`, exact Q8_0 `MODEL_FILENAME`, 64-hex `MODEL_SHA256` and model license/provenance independently. Stop if unavailable. Record image source commit, reviewed scan/SBOM, amd64 image digest, CUDA 12.8.1 and offload requirement. Separate authorization is required to publish; deploy by **digest**, not branch/tag. No weights in image, remote model downloads, volumes or fallback GPU. Ensure any private GHCR pull credential is read-packages-only.
3. Requote the **Serverless** 16 GB flex tier in the actual console. [Public pricing](https://www.runpod.io/pricing), updated Nov 12 and read Nov 25, 2026: $0.58/hour for A4000/A4500/RTX 4000/RTX 2000; [endpoint settings](https://docs.runpod.io/serverless/endpoints/endpoint-configurations) rounds to $0.00016/s. Use the higher rate. One worker for **30 minutes including teardown** gives $0.29 compute; 20 GB container disk at approx $0.10/GB-month for seven 5-minute intervals is ~$0.0017 (30-day month). **Estimated maximum $0.30 under these assumptions**, excluding tax, unrelated usage, paid transfer, retries/replacements beyond window or delayed teardown. Stop before creating if quoted disk/rate/fees/region invalidate estimate. A quote, max workers and a timer are **not a provider spending cap**. At 25 minutes stop requests and begin deletion, regardless of test progress. Escalate immediately if still billed at 30.
4. [Billing](https://docs.runpod.io/serverless/pricing): provider-managed cache download and container pull normally precede billed worker startup; cache verification, CUDA load, inference and running idle are billed. No paid network volume. Confirm any image-registry egress, storage and transfer overhead; do not assume all downloads anywhere are free. Check actual disk requirement against selected image. Q8 weights plus KV cache/context and CUDA workspace must fit; 16 GB is a candidate, not a measured guarantee.

## Dedicated endpoint

1. In Serverless -> New Endpoint -> Import from Docker Registry, enter the reviewed `ghcr.io/5tannerpl/aob-llama-serverless@sha256:...`. Choose **Load Balancer**, private/authenticated incoming requests only. Use a unique PoC name. Do not select a queue worker, Pod, vLLM template or GitHub auto-deploy.
2. One approved 16 GB compatible GPU category only, one GPU per worker, active workers **0**, max workers **1**, container disk **20 GB**, no persistent volume, compatible CUDA driver filter (12.8 or verified newer). Configure idle timeout **5 s**, FlashBoot **off**, `RUNPOD_INIT_TIMEOUT=210`. Review console values before deployment; if supported only via a subsequent edit with higher billing risk, stop. Provider LB has its own request/processing limits; job TTL is not a guard here.
3. Set Model to the approved HF repo. No general HF token for a public repo; for a gated one require separately approved model-read-only token in provider secret storage. Set `MODEL_SOURCE=cache`, all four model pins, `PORT=8080`, `PORT_HEALTH=8080`, health check `/ping`. Configure only the required application HTTP port per [LB docs](https://docs.runpod.io/serverless/load-balancing/overview); no raw TCP/public IP, SSH, metrics, backend or alternative routes. If the console requires direct exposure, confirm authentication/bypass policy before continuing.
4. Generate a dedicated random **application** secret (at least 32 bytes) as `INFERENCE_KEY`. Set `AOB_INFERENCE_TELEMETRY=true`, optionally `AOB_INFERENCE_GPU_OBSERVATIONS=true`. Do not set management, Azure, OCI or OTLP credentials in the container. Callers need an endpoint-restricted Serverless invoke key ([permissions](https://docs.runpod.io/get-started/credentials)) **and** the separate application secret. Operator console permissions to create/edit/delete just the dedicated resources and read billing are not caller credentials. Use redacted local tooling; no shell tracing, verbose HTTP, notebook output containing headers, or secrets in URLs.
5. Start the wall timer and click Deploy Endpoint **only after sign-off**. Record endpoint ID, region, account, resolved image/version, model selection, rate and worker settings without credentials. If these cannot be confirmed, abort and delete.

## Measurements

* From scale zero record client wall time and monotonic elapsed time. Send one authenticated synthetic POST to `https://ENDPOINT_ID.api.runpod.ai/v1/chat/completions` with `Authorization: Bearer <endpoint key>`, `X-Inference-Key: <application key>`, unique synthetic W3C `traceparent`, `tracestate: aob=poc`, `X-AOB-Run-ID` and `X-AOB-Unit-ID`. Body: `{"model":"Qwen3-4B-Instruct-2507","messages":[{"role":"user","content":"Reply with the word green."}],"temperature":0,"max_tokens":12}`. No automatic retries. If capacity times out, record the failed attempt; never silently relabel a later warm result as cold.
* Record the worker instance, provider Worker/Metrics screenshot, clean resolving/loading/ready transitions, checksum identity, load duration and full-layer CUDA evidence. Verify against expected GPU type and device observation. A `/ping` 200 by itself is not G3 evidence. Distinguish client cold latency, provider 204->200 interval and process timings. Log only request ID, trace linkage, timings, status, token usage and derived completion tokens/s **with its denominator specified**; if generation-only time is unavailable do not call end-to-end throughput decoding speed. Inspect synthetic output privately for actual inference. Missing GPU samples are unknown.
* Immediately send one warm POST while worker is still running; stream one pair with `stream:true,stream_options:{"include_usage":true}`. Capture time to first content (stream), `[DONE]`, totals and whether events arrive incrementally at the client. Check the same instance and matching parent trace ID; note any stripped headers. Verify missing/wrong provider bearer is rejected at edge and correct bearer without app key is rejected at gateway; neither may trigger inference. If any unauthorized request succeeds, abort. Do not leak credentials to test additional routes.
* Stop traffic, including `/ping` and UI auto-tests. Observe Workers/Metrics **out of band** through idle timeout until no running GPU worker; distinguish waiting/Running from scaled-down/Idle. Record actual observed timestamps and limitations, not invented release events. Repeat to target **three cold and three warm** measurements total, within original budget/window. Skip rather than exceed it. Do not increase max workers. If FlashBoot/fresh identity cannot be distinguished, mark cold timing inconclusive.
* Abort immediately on wrong cache/hash/driver, failed or repeated initialization, partial/no offload, fallback selection, unexpected active count/charge, bad auth, content leakage, deadline exhaustion, ambiguous state or inability to observe/stop. Stop sending requests; never fix forward by switching quantization, adding a volume or extending the budget.

## Teardown and reconciliation

Record evidence before removal without keeping workers warm. In Serverless select the **exact dedicated ID**, Manage -> Delete Endpoint; verify gone from inventory and no running worker remains. Do not delete shared templates, volumes, images, or the owner's resources. Revoke dedicated invoke/app secrets and dedicated registry/HF credentials; remove any test-only template if independently identified and approved. Confirm no unexpected storage resources. If deletion cannot be confirmed, escalate with ID and timestamps, keep monitoring billing, and do not claim zero cost.

Compare usage export/billing ledger and ending balance to starting inventory, endpoint ID, running seconds, rounding, rate and storage intervals; recheck after posting lag. Record unexplained charges separately. Provider metrics, local NVML samples and wall-clock estimates are not invoices. File redacted evidence and discrepancies; G3 remains open until reviewed. No later phase or paid end-to-end execution is authorized by a successful standalone test.
