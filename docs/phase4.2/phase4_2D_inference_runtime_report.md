## Runtime contract

Set `PORT=8080`, `PORT_HEALTH=8080` explicitly; distinct unprivileged ports are supported. Only `GET /ping`, `GET /readyz` and `POST /v1/chat/completions` are intended for exposure. Health reveals no identifiers or internals. `INITIALIZING`, `RESOLVING_MODEL`, `LOADING_MODEL`: `/ping` 204, `/readyz` 503. `READY`: both 200 only while private llama `/health` says `{"status":"ok"}`. `FAILED`/`DRAINING`: unavailable (503 while listening, otherwise closed). No internal restart. Verify pins, launch loopback `127.0.0.1:18081`, explicit CUDA0, `-ngl 99`, context 4096, one slot, auto-fit off, offline mode, no UI. Require positive full `N/N layers to GPU` observation from pinned llama startup and HTTP readiness; discard arbitrary child output. Bounded startup 180 s plus one-second watchdog; TERM stops admission, drains HTTP up to five seconds, signals child then kills/reaps on timeout.

Inference requires a separate `X-Inference-Key` matching operator secret `INFERENCE_KEY` (32-256 bytes), **in addition to** the LB bearer at provider edge. Local/private deployments must use trusted TLS ingress, restrict direct port access, and keep the backend on loopback. No redirects, configurable upstream, forwarded bearer, prompt logging or management endpoints. Clients may send only the fixed alias `Qwen3-4B-Instruct-2507`, 1-64 text messages (system/user/assistant), temperature 0-2, max_tokens 1-1024 (default 600), optional `response_format` text/json_object and bounded SSE options. One request at a time; overload 429, not queued. Input 64 KiB, output 1 MiB, 2 s upstream dial, 120 s inference/client write deadline. Reject unknown/duplicate/null fields. Return projected OpenAI choices/usage and a generated request ID; no upstream body on error. For partial SSE failures terminate without `[DONE]`; missing terminator is not success.

## Observations and future integration

Off by default. `AOB_INFERENCE_TELEMETRY=true` enables nonblocking queue (64) to local JSONL stdout; bounded loss under pressure, counts on subsequent successful records. Only structured fields; no exporter URL/key or ingestion authority. Events are **not OTLP spans**. Capture per-process runtime instance, model, observed checksum/load and ping 204-to-200 interval only when observed (not necessarily provider cold-start time), trace/span/request IDs, SHA256 correlations for validated `X-AOB-{Run,Unit,Worker,Deployment,Source,Correlation}-ID`, optional positive attempt, status/duration and measured usage. Valid v00 W3C parent becomes a child; invalid/missing starts local root; only `aob` vendor tracestate forwarded. `AOB_INFERENCE_GPU_OBSERVATIONS=true` additionally samples device 0 via NVML-backed `nvidia-smi` every 30 s; unsupported fields absent, no implicit zero, Agent ownership, replica counts, or GPU-release events. Validate export isolation and correlation later; a SHA correlation is pseudonymous, not authorization.

Future Agent-side [InferenceProvider.generate](../../crosscloud/providers.py) can send its system/user messages and translate `choices[0].message.content`; honor caller deadlines, request ID, error/usage semantics and the existing [llama request shape](../../workers/model_client.py). Do not use the management client, add `/props` passthrough, join traces by remote ID alone, or treat a receipt as completion.
