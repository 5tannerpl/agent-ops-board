### Acceptance gates

- **Happy path:** actual no-parent fixture returns 100 completed, zero failed, 100 true validations, four workers (25 units each), 100 unique units, six expected raw name counts and 405 distinct spans in one trace. Independently join the 404 internal edges by trace + span; confirm exact worker/unit ancestry and sibling steps, not just totals. Read `PARTIAL` before manifest, `TRACE_COMPLETE` afterwards. `AZ/evidence/span-report.json:2-18`, `AZ/verify_capture.py:23-54`.
- **Boundaries and cardinality:** repeat with inbound W3C parent; distinguish one declared external edge from a missing internal parent. Split across batches out of order, lose a parent, introduce a cycle, then test late arrival after finalization. Same run with two traces and reused span IDs across traces; same run/trace/span values in two authorized source namespaces; identity conflict within one source. Each caller sees only authorized data. Motivated by `B/otlp_store.py:33-68,137-150`, `B/demo_api.py:286-300`.
- **Outcomes:** failed unit with and without completed validation; retry on a different worker; missing or contradictory outcome. No double-counting of failed attempt plus later success, no positive validation inferred from presence. Azure business failure and telemetry failure tested independently (`AZ/tests/test_runs.py:106-139`).
- **Transport and privacy:** absent/wrong source token, wrong MIME, malformed/empty/oversized batch, invalid required ID/timestamp or parent; replay and duplicate ack; partial success with nonzero rejects. Enforce typed allowlists and no payload secrets. Verify manifest counts are validated and scoped to authenticated source; private reads do not accept ingest-only credentials. `B/config.py:89-105`, `B/otlp_api.py:15-49,65-120`, `AZ/tests/test_transport.py:30-88`.
- **Compatibility:** unmodified Azure producer still ingests; old summary route/keys remain usable. Signed Kaggle batch/time/ID formats, final flag, run ownership, chat-to-unit correlation, integer job IDs, token coverage and GPU event counters still work. Old rows remain visible; absence is not zero. `B/trace_store.py:11-39,82-116,189-225`, `B/tests/test_trace_observability.py:40-71`, `B/workers/worker.py:95-100`, `B/security/event_schemas.py:191-239`.

**Rollout and fallback proposal:** add nullable storage and v1 reads first; compare legacy and v1 views on fixtures before opting any producer into completion. If the comparison fails, keep legacy reads/writes and stop enabling v1; do not delete old rows or weaken checks to make the verifier pass. Historical re-ingestion requires retained, authorized evidence and explicit reconciliation, not a blind duplicate upload. Phase 4.1-A delivers documents only; implementation requires separate approval.
